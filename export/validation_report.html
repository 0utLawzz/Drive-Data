⚠️ Confirmed Parser Bug

Bug in parse_case_folder() — 2-digit Case Numbers not recognised

The regex ^[A-Z]\d{3}-\d{3}$ requires exactly 3 digits before the dash (e.g. A001-001). The real Brandex dataset contains folders with 2-digit prefixes such as A52-029, A54-005, A51-016. These are valid Case Numbers but the regex fails to match them — they are silently classified as [OTHER] tokens and the Case # field is left blank.

Impact: 173 case folders have a valid TM No but an empty Case # solely because of this mismatch. Patterns 1, 2, 3, and 9 in the table above are all instances of this one bug.
